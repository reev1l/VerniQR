# ВерниQR

Рабочий MVP: Telegram-бот для владельца, мобильная страница для нашедшего и SQLite.
Владелец создаёт до трёх вещей, получает PNG/PDF с постоянными QR, выбирает публичные
контакты и обрабатывает обращения в Telegram. Нашедшему регистрация не нужна.

## Быстрый запуск на этом компьютере

Сначала **полностью распакуйте архив** в отдельную папку. Не запускайте файлы
из окна ZIP. Для подключения к Telegram:

1. Для проекта выбран **@verniQRbot**. Откройте **@BotFather** в Telegram,
   выполните `/mybots`, выберите этого бота и откройте **API Token**.
2. Дважды нажмите **`setup-env.cmd`** или **`Настроить бота.cmd`**: он создаст `.env` из шаблона, если
   файла ещё нет, и откроет его в Блокноте. Существующие настройки не перезаписываются.
   В этом файле заполните `BOT_TOKEN`. Поле `BOT_USERNAME=verniQRbot`
   уже подготовлено. Не публикуйте этот файл. При создании отдельного тестового
   бота укажите его собственные username и токен.
3. Пока можно оставить `PUBLIC_URL=http://localhost:8000`: бот работает, но ссылки
   открываются только на этом компьютере. Для телефона и реальных меток нужен
   общедоступный HTTPS-адрес сервера.
4. Запустите `start-windows.cmd`. При первом запуске он создаст `.venv` и установит
   зависимости; для этого нужны установленный Python 3.11+ и интернет. На компьютере,
   где зависимости уже установлены, повторная загрузка не нужна. Дождитесь завершения
   и оставьте окно работающего бота открытым. Для запуска вручную после установки:

```powershell
.\.venv\Scripts\python.exe -m verniqr run
```

5. Откройте своего бота, нажмите «Запустить» и отправьте `/id`.
6. Впишите полученный номер в `ADMIN_IDS` в `.env` и перезапустите приложение.
7. Создайте карточку. От своего администратора отправьте `/activate ВАШ_ID 30`.
   Теперь можно получить PNG и PDF. Для пилота активируйте пользователей после
   ручного подтверждения оплаты.

Чтобы посмотреть веб-страницу без токена:

```powershell
.\.venv\Scripts\python.exe -m verniqr run --web-only
```

Откройте `http://localhost:8000/demo`. Демонстрационная форма не создаёт настоящие
обращения. В режиме `--web-only` Telegram не подключается и уведомления не отправляются.
Если открыть активную личную метку в этом режиме, обращения сохраняются в очередь
и будут доставлены после обычного запуска с ботом.

Если при запуске не удаётся подключиться к `api.telegram.org:443`, бот повторит
подключение до трёх попыток. Проверьте доступ к [Telegram Bot API](https://core.telegram.org/bots/api#making-requests)
с того же компьютера без токена: `curl.exe -I --connect-timeout 6 https://api.telegram.org/`.
HTTP-ответ, включая перенаправление или ошибку HTTP, означает, что соединение установилось.
Если запрос истекает по тайм-ауту, попробуйте другую сеть или сервер, с которого
доступен API. Для просмотра только сайта: `.\start-windows.cmd --web-only`.

Если Telegram доступен через уже настроенный системный прокси Windows, задайте
`TELEGRAM_USE_WINDOWS_PROXY=1` в `.env`. Бот возьмёт адрес из настроек Windows.
Проверка HTTPS-сертификата остаётся включённой. После изменения настроек
прокси перезапустите бота.

## Установка на другой компьютер

Нужен Python 3.11 или новее.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock
.\.venv\Scripts\python.exe -m pip install --no-deps -e .
.\.venv\Scripts\python.exe scripts/prepare_env.py
```

В Linux/macOS используйте `.venv/bin/python` вместо `.venv\Scripts\python.exe`.
Для PDF нужен шрифт с кириллицей: в Windows используется Arial, в Docker установлен
DejaVu Sans. При другом размещении установите DejaVu Sans или задайте
`PDF_FONT_PATH` — абсолютный путь к подходящему TTF.

## Возможности владельца

| Команда | Действие |
|---|---|
| `/start` | Зарегистрировать профиль и открыть меню |
| `/items` | Список вещей, контакты, переименование, удаление и выдача меток |
| `/new` | Создать карточку с названием до 100 символов |
| `/reports` | Новые и закрытые обращения, по пять на страницу |
| `/subscription` | Срок доступа, цена и порядок ручной активации |
| `/demo` | Открыть демонстрационную страницу |
| `/id` | Узнать свой Telegram ID |
| `/help`, `/terms` | Инструкция и сведения об обработке данных |
| `/cancel` | Отменить текущий ввод |
| `/delete_me` | Удалить профиль после ввода слова «УДАЛИТЬ» |

В карточке можно добавить, изменить, скрыть или удалить каждый из трёх контактов:
телефон, публичный Telegram username и email. Новые контакты сразу становятся
видимыми на активной странице; бот предупреждает об этом до ввода. По умолчанию
контактов нет, доступна только форма.

Файлы меток выдаются после активации. PNG имеет размер 300 × 300 пикселей и белое
поле вокруг кода. PDF — лист A4 с меткой 90 × 105 мм и инструкцией. Печатать в масштабе
100%; пользователь вырезает и прикрепляет метку самостоятельно.

После возврата закрывается только выбранное обращение. Карточка, QR и другие
обращения остаются доступны. Повторная находка создаёт новое обращение.

## Команды администратора

Доступ разрешён только Telegram ID из `ADMIN_IDS`. Все действия выполняются в личном чате.

| Команда | Действие |
|---|---|
| `/admin` | Справка администратора |
| `/owners` | Владельцы, количество вещей и сроки доступа |
| `/stats` | Владельцы, активные доступы, карточки, обращения и ошибки уведомлений |
| `/activate 123456789 30` | Добавить 30 дней доступа владельцу |
| `/revoke 123456789` | Немедленно отключить публичные страницы владельца |

Владелец должен сначала нажать `/start`. Продление добавляется к оставшемуся сроку;
если срок истёк, отсчёт начинается с момента активации. Допустимы 1–366 дней.
Сроки показываются явно в UTC. Изменения доступа фиксируются в журнале базы данных.

Автоматической оплаты и бесплатной активации по умолчанию нет. Цена в настройках —
50 ₽ в месяц; администратор вручную проверяет оплату и назначает срок.

## Публичная страница

`GET /item/{uuid}` показывает название вещи, выбранные контакты и форму.
Сообщение после удаления краевых пробелов должно содержать 10–1000 символов.
Обратный контакт необязателен, не более 200 символов. Файлы не принимаются.

Форма отправляет JSON в `POST /api/reports/{uuid}` с подписанным `X-Form-Token`,
выданным при открытии страницы. Токен действует сутки и привязан к вещи. Повтор
того же запроса с тем же токеном возвращает успех без создания дубликата; изменение
содержимого при повторе даёт 409. Для нового обращения нужно заново открыть страницу.

```json
{"message": "Рюкзак оставлен у охраны корпуса Б", "finder_contact": "@finder_name"}
```

Первое сохранение — HTTP 201, повтор — 200. Ответ подтверждает **сохранение**, а не
прочтение или доставку в Telegram. Ошибки: 400 — данные, 403 — токен/источник,
404 — неактивная метка, 409 — конфликт повтора, 413 — большой запрос,
415 — формат запроса, 429 — частота, 503 — ошибка базы.

По умолчанию разрешено 10 сообщений с одного IP и 5 сообщений по одной вещи
за 10 минут. Лимиты задаются в `.env` и сохраняются при перезапуске приложения.
Для ограничения используется HMAC IP, исходный IP в базу не записывается.
Устаревшие записи ограничителя удаляются при запросах и примерно раз в минуту.

Страницы и обращения защищены проверкой владельца, экранированием пользовательского
текста, политикой CSP, запретом индексирования и кэширования. Скрытые контакты не
передаются в HTML. UUID — публичный адрес для связи, он не даёт права управления.

## Доставка сообщений и данные

Обращение и запись очереди уведомлений сохраняются одной транзакцией. После этого
фоновый обработчик отправляет уведомление с кнопками закрытия в Telegram. При сбое
обращение остаётся в списке; владелец может нажать «Повторить уведомление».
Незавершённая отправка подхватывается после истечения двухминутной аренды.

Telegram не предоставляет ключ идемпотентности для `sendMessage`: если процесс
остановится после отправки, но до записи результата, уведомление может прийти
повторно. В базе при этом остаётся одно обращение с прежним номером.

Карточки и обращения хранятся до удаления вещи или профиля. После окончания
подписки публичные контакты и форма отключаются; старые обращения доступны
владельцу. Продление включает тот же QR.

Удаление профиля удаляет связанные карточки, контакты, обращения, записи
ограничителя и журнал активаций из рабочей базы. Копии хранятся до семи дней.
Ранее отправленные в Telegram сообщения и файлы могут оставаться в истории чата.
Незавершённый диалог ввода хранится в памяти и сбрасывается при перезапуске;
сохранённые карточки, подписки, обращения и очередь от этого не зависят.

## Размещение на VPS с HTTPS

В комплекте есть Dockerfile, Compose и Caddy для получения HTTPS-сертификата.
На сервере установите Docker с Compose, направьте домен на сервер и откройте
входящие порты 80 и 443. В серверном `.env` задайте:

```dotenv
BOT_TOKEN=токен_от_BotFather
PUBLIC_URL=https://ваш-домен.ru
DOMAIN=ваш-домен.ru
ADMIN_IDS=ваш_числовой_Telegram_ID
APP_SECRET=случайная_строка_не_короче_32_символов
SUPPORT_CONTACT=@контакт_организатора
```

Секрет можно создать командой `python -c "import secrets; print(secrets.token_hex(32))"`.
Используйте стабильный домен: смена `PUBLIC_URL` не обновит уже напечатанные метки.
Для тестового и рабочего ботов используйте разные токены и базы данных.

```sh
docker compose up -d --build
docker compose logs --tail=50 app
```

Публично доступен только Caddy; порт приложения не публикуется. Caddy подставляет
проверенный адрес клиента для ограничителя отправок. Настройка доверия всем
прокси применяется только внутри этой закрытой сети. При другом размещении
задайте `TRUSTED_PROXY_IPS` адресом своего прокси и не открывайте внутренний порт
приложения при значении `*`.

Запускайте один процесс и один экземпляр бота на токен. Файловая блокировка
предотвращает одновременный запуск на одной базе. `/healthz` проверяет базу и
состояние фоновых задач; журнал запросов с адресами карточек отключён.

## Резервные копии и восстановление

При запуске создаётся первая проверенная копия, затем — примерно раз в сутки.
Копии старше семи дней удаляются примерно раз в минуту, пока сервис работает.
Если сервис остановлен, очистка возобновляется при запуске.

```powershell
.\.venv\Scripts\python.exe -m verniqr backup
```

Копирование использует SQLite backup API и учитывает WAL. Файлы сохраняются
в `BACKUP_DIR`. При размещении на сервере организуйте отдельное защищённое
хранилище копий с тем же сроком хранения: локальная копия не защищает от потери VPS.

Для восстановления остановите сервис:

```powershell
.\.venv\Scripts\python.exe -m verniqr restore data/backups/ИМЯ_КОПИИ.sqlite3 --confirm
```

Перед заменой проверяются структура и целостность. Текущая база сохраняется
как `before-restore-*`. При работающем сервисе восстановление блокируется.

Для Docker: сначала `docker compose stop app`, затем
`docker compose run --rm --no-deps app python -m verniqr restore /app/data/backups/ИМЯ_КОПИИ.sqlite3 --confirm`,
после этого `docker compose start app`.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m ruff check verniqr tests
```

Проверки охватывают сценарии A1–A12: лимит карточек, видимость контактов,
чтение QR из PNG и PDF, сохранение обращений, сбои Telegram/базы, дубликаты,
чужой доступ, закрытие, повторную находку, окончание доступа и восстановление.
Отдельно проверяется обработка настоящих Telegram Update через диспетчер с
подменённым транспортом: создание, контакты, файлы, обращения, администрирование
и подтверждение удаления. Настоящие сообщения при тестировании не отправляются.

Перед пилотом вручную проверьте весь сценарий с настоящим токеном и HTTPS,
а также сканирование напечатанной метки камерами iOS и Android. Автоматическое
чтение изображения не заменяет проверку физического отпечатка. Docker-конфигурация
подготовлена; сборка и получение сертификата проверяются на целевом сервере.

Не входят в MVP: фотографии, геолокация, SMS, двусторонний чат, автоматическая
оплата, производство и доставка меток. Это соответствует согласованным границам.

## Основа реализации

Архитектура следует документам проекта: aiogram 3, FastAPI и SQLite.
Контракты жизненного цикла FastAPI и диспетчера aiogram сверены с официальными
руководствами: https://fastapi.tiangolo.com/advanced/events/ и
https://docs.aiogram.dev/en/latest/dispatcher/dispatcher.html.
